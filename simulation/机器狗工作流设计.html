01🎯

系统总览与角色分工

机器狗在库管调度系统中的定位：只扫码核验，不搬运钢材

本系统是 300m × 90m 三跨棒材库区 的流程级调度仿真。钢材捆上贴有二维码，机器狗（四足机器人）承担全库的“扫码核验”环节： 入库时到天车落料的库位扫码确认入账，出库时到吊走后的垛位扫码核销，倒垛后到源/目标两垛双点核验—— 扫码结果回传 WMS 后库存才正式更新，保证账物一致。钢材的物理搬运全部由天车 + 吊运工完成。

300×90 m库区总长 × 宽
3 跨A / B / C，每跨 30m
91 库位每库位 10 垛（可配）
3 台机器狗（1–6 台可调，D-01 起编号）
6 台天车（每跨 2 台）
6+1 名库区吊运工 + 每车 1 名车上专职
3 通道竖向车辆进出通道
4 廊道2m 横向通道 = 机器狗主动脉

🐕 机器狗（本页主角）

扫码核验员。沿横向廊道与库位间空道机动到目标垛位正前方，转身面向垛位扫描二维码， 完成入库入账 / 出库核销 / 倒垛双点核验；同一垛位的积压待扫任务归并为一趟，到场连续扫完、不重复跑； 低电自动返航充电。行进 5 m/s、单次扫码 120s、满电续航 3h。

🏗 天车

唯一的钢材搬运设备。大车 4 m/s（沿厂房长向）、小车 1 m/s、吊取 2s / 放下 1.8s； 一车一天车：一辆货车的装卸全程由同一台天车完成，单跨作业。

🧍 吊运工

人因环节三段分工：吊前挂绳 60s（穿绳上钩）→ 落位放绳 45s（取钩，入库/倒垛吊绳随捆留垛）→ 出库取绳 30s（车上抽绳收回，不挡天车、挡货车复验离场）。出入库货车每车另配 1 名车上专职。

🚚 货车 + 📷 立柱摄像头

3 条竖向通道进场、停靠目标跨；跨上立柱摄像头识别车牌（2s），凭车牌从物流系统吊取运单（1.2s）； 出场复验 1.5s（装卸数量与运单复核）。

🗄 WMS / 调度引擎

下发入库 / 出库 / 倒垛确认任务；就近分配 + 电量约束派单给机器狗，同垛位任务归并同一趟 （到场/扫完每捆时再捎带新落料/新吊走的同垛任务）；扫码回传后更新库存数据库并台账留痕； 管理工在「进厂确认」工作台保留最终决策权。

端到端主链：货车进场停靠 → 跨上立柱摄像头识别车牌 → 物流系统吊取运单 → 吊运工挂绳 → 天车吊运装卸 → 吊运工放绳 / 取绳 → 机器狗扫码确认 → 库存更新。 一车 6–10 吊，单跨装卸；任务保持“吊”粒度（1 任务 = 1 规格 → 1 库位），机器狗 / 天车 / 库存 / KPI 均按吊计数。
02🔁

端到端业务流程

入库 / 出库 / 倒垛 三条主流程全环节拆解（含各环节耗时与责任角色）
流程 A

入库流程（进厂卸货 → 扫码入账）

触发：进厂货车随车运单（一车 6–10 吊，整车单规格为主，部分混装）
1
货车进场停靠
货车经 3 条竖向通道进场，按任务目标跨停靠车位；场内行驶 8 m/s。
2
识别车牌识别 2s
跨上立柱摄像头自动识别车牌，作为该车全部业务的索引键。
3
识别吊取运单 1.2s
凭车牌从物流系统调取随车运单（规格 × 吊数）；运单与实货差异率 5% 时以现场扫码数据为准修正。
4
吊运工挂绳 60s / 吊
库区班组把吊绳穿上钢材捆并挂上天车吊钩；车上另有 1 名专职吊运工配合车上绳索。
5
天车吊运落料 吊取 2s + 放下 1.8s
按归堆推荐评分选定目标库位/垛（同规格归堆、先填满旧垛、邻位聚簇、避让待扫码垛），天车把钢材从车上吊到目标垛。
6
吊运工放绳 45s
落位后把吊绳自吊钩取下；入库吊绳随捆留垛，供下次出库直接挂钩。
7
机器狗扫码核验 120s/捆 ← 账物一致关口
天车落料后任务才可派单（materialReady）。机器狗经廊道+库位间空道到垛位正前方站位，转身面向垛位扫码， 捆标签与库位/垛绑定；同垛积压的待扫任务原地连续扫完（同车多吊集中落同垛时不再逐捆跑腿）；失败原地重扫 ≤2 次，连续失败转人工介入。
8
库存入账闭环
待核验捆转为在库（捆级明细确认），写回库存数据库，任务台账留痕；同车多吊集中同垛时按计数逐捆核销。
流程 B

出库流程（提货订单 → 扫码核销）

触发：提货订单（合同号 + 需求捆数，全天铺开下发）；天车先吊走，机器狗随后扫码核销
1
WMS提货订单下发
按合同号 + 需求捆数生成出库订单，在办订单上限 16 个，防队列失控。
2
调度订单配捆
该规格在库已扫码捆中随机选捆；目标捆被压（上方整层压货）→ 先触发倒垛（见流程 C）； 无倒垛落点最长等待 1800s，超时换捆重配防库位锁死。
3
货车空车进场 + 识别 2s + 1.2s
空车进场停靠目标跨，车牌识别 + 运单吊取确认后，天车作业条件齐备。
4
吊运工挂绳 60s
库位侧班组对目标捆挂绳（入库时留垛的吊绳可直接挂钩）。
5
天车吊运装车
天车先行把钢材吊离垛位装车；物料吊走时刻（liftedAt）是出库扫码延时统计起点，此后机器狗才可获派。
6
吊运工取绳 30s
出库落车后把吊绳自钢材捆中抽出收回；不挡天车，但挡住货车复验离场。
7
机器狗扫码核销 120s ← 账物一致关口
机器狗到原垛位前扫码，确认“出库吊走后垛位余量与台账一致”；与装车完成互为双条件，后到者触发任务闭环。
8
货车出场复验 1.5s
装卸数量与运单复核（异常率 3%，人工复核后放行），复验通过货车离场。
9
库存核销闭环
装车完成 + 扫码确认核销双条件齐备，订单履约推进，库存数据库同步核销。
流程 C

倒垛流程（压货挪移 → 双点核验）

触发：出库目标捆被上方整层压货；倒垛后机器狗源垛 + 目标垛双点扫码
1
调度倒垛触发
配捆时发现目标捆被压：需在装车前把上方整层压货挪至同库位其他垛；无落点则等待（上限 1800s）后换捆重配。
2
WMS下发倒垛任务
倒垛任务进入天车作业队列（与出入库吊统一调度）。
3
吊运工挂绳 60s → 天车挪移压货 → 吊运工放绳 45s
压货整层挪至同库位目标垛，吊绳随捆留垛；库存在天车落位时即完成物理迁移。
4
WMS下发倒垛确认任务
事后核验、不阻塞该车装车吊；源/目标两垛均在扫描范围内才派机器狗，否则整单免检直通 / 转人工核对。
5
机器狗源垛扫码 120s
确认压货捆已挪走、垛顶物资与台账一致。
6
机器狗转场目标垛扫码 120s
源垛扫毕自动规划转场路径，到目标垛前扫第二点，确认倒垛落位捆与台账一致（转场受阻则整单重排、从目标垛续扫）。
7
库存留痕闭环
双点核验一致后留痕闭环（不改动库存——库存已在落位时迁移）；出库装车流程继续。
为什么出库是“先吊走后扫码”？ 钢材一旦吊离垛位即不可逆地开始装车节拍，机器狗无须挡在天车前； 改为吊走后到原垛位核验“余量与台账一致”，扫码与装车并行，任务闭环取两者后到者——既保住账物一致，又不拖累天车节拍。

04🧮

任务调度引擎

先到先服务 + 就近分配 + 电量约束 · 每仿真拍运行一次

调度器（scheduler()）对 pending 任务队列按先来后到逐单尝试派狗，每单在可用机队中择优：

规则内容
① 派单前置入库单：天车落料就位（materialReady）后才可派扫码；出库单：物料吊走（liftedAt）后才可派核销——扫码与吊运不互相等待。
② 范围旁路先于派单处理：库位不在扫描范围内 → 免检直通 / 转人工核对（不占机器狗、不等机队）；倒垛确认需源/目标双垛均在范围内才派狗。
③ 可用判定IDLE 立即可用；CHARGING 中电量 ≥ 85% 亦可接单（打断充电，留痕中断时刻电量）。
④ 就近分配对每台可用狗求解到“目标垛前空道站位”的路径长 d1，取 d1 最小者；路径不可达（∞）直接跳过该狗。
⑤ 电量约束预估全程电耗 + 返桩电耗 + 安全余量，电量不足不派——保证任何已派任务做完一定能回桩。
⑥ 阻断兜底所有狗都不满足 → 任务留在队列下一拍重试；执行中寻路失败 → 任务重排队，通道间隙释放后自动再派。
need = ( d1（当前位置 → 垛前站位） + d2（倒垛：源垛 → 目标垛转场） + d3（站位 → 本狗充电桩） ) × drainPerM 派单条件： battery ≥ need + reserve（安全余量 12%）；多台满足时取 d1 最小
分配日志示例：调度分配：T-XXXX → D-02（扫码路程 87m · 电量 76%）。 倒垛确认两点任务的电量预留会把“源垛 → 目标垛”转场段一并加算，避免扫完第一点却走不到第二点。

异常与兜底设计

异常注入概率均可在「调度参数 · 异常注入」页调整（0 = 关闭）
异常场景概率 / 参数处置策略留痕与影响
扫码失败（码面污损 / 反光） scanFailPct 4% 原地重扫，最多 maxScanRetries = 2 次；仍失败 → 人工介入核验放行，不阻断流程。 异常计数 + 日志留痕；任务标 anomaly；该捆耗时拉长。
运单与实货差异 manifestMismatchPct 5% 以机器狗现场扫码数据为准修正（数据融合优先级：现场扫码 > 门卫录入 > 运单）。 修正留痕；库存按实物入账。
出场复验异常 verifyIssuePct 3% 人工复核后放行。 复验环节延时，货车离场推迟。
扫描范围外任务 监测跨 × 号区配置 监测跨内、扫描号区之外 → 转人工核对；未监测跨（或三跨全关）→ 免检直通，直接产生与扫码完成相同效果。 不派狗、不占机队；时效页按“人工核对 / 免检”分别标记，延时≈0。
路径阻断 动态（垛位占用） 派单时跳过不可达狗；执行中寻路失败 → 任务重排队；返航被堵 → 原地等待逐拍重试。 系统日志告警；间隙释放后自动恢复。
倒垛无落点 restackWaitMax 1800s 目标捆被压且无倒垛落点时最长等待 1800 仿真秒，超时换捆重配，防库位锁死。 出库订单履约延后；任务日志留痕。
库满暂缓 动态（容量） 入库吊暂无落点 → 转补配队列（inDebt），容量释放后自动续配，不丢吊。 排产日志注明暂缓吊数。
队列失控防护 上限 48 / 16 待处理任务上限 48、在办出库订单上限 16，到顶暂停新任务下发。 防内存与节奏失控。
