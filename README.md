# 钢厂库区调度系统

机器狗扫码调度仿真沙盘 + 库存数据库 + 管理工工作台，全部由一个本地站点提供：
`npm run sim` 后访问 **http://localhost:5199/**

> **仿真场次（默认不启动）**：沙盘打开后**暂停待命**，点击「▶ 启动」开跑一场；
> **重置**或**关闭页面前**该场自动归档 —— 记录当场的**调度参数**（启动时 + 归档时两份快照，可对照中途调整）、
> **车辆记录**（车牌/方向/吊数/进出场时间）与**扫描时效**（扫码延时均值/P95/最大）+ KPI，
> 在 `/runs` 仿真场次页回看 / 导出 CSV（本浏览器 localStorage，环形保留最近 50 场）。

> **车辆数据来源（默认本地）**：沙盘**自己排产**生成进厂车（随车运单 6-10 吊）与提货订单，
> 按「生产节奏」参数（每日进厂/出厂辆数，见「调度参数」页）均匀铺到全天，**无需任何外部程序**。
> 如需接入外部物流源 [LogisticsData_Sim](../LogisticsData_Sim)（`npm start` 启动后打开 `http://localhost:5199/?feed=all`）：
> 沙盘从同一条持久化事件流消费车辆事件——`?feed=all` **全量回放**（期初按数据库种子分布重建，
> 同一标签页刷新自 sessionStorage 游标**断点续接**，不重复入库）；`?feed=live` 只跟最新事件（跳过历史）；
> `?view=1` **只读观景**（不写回库存数据库、不落台账，多开对照安全）。
> 「进厂确认」页的「模拟车辆进厂」始终优先取物流源下一辆进厂车（源离线时自动回退本地随机）；
> 数据库服务还会**每 2s 自动轮询**物流源，把每辆进厂车实时登记进「进厂确认」队列（待确认）——
> 确认队列 / 「车辆记录」与沙盘消费的是同一条事件流，三个页面车辆一一对应（沙盘须 `?feed` 模式；
> 沙盘**本地排产模式**的车只存在于页面内存，不进数据库，与两页无从同步，属已知语义）。

### 物流数据源接入（可选，LogisticsData_Sim）

默认**无需**物流数据源（沙盘本地排产）。需要多实例同进度对照时：

```bash
# 1) 启动车辆进出库物流数据仿真（事件流持久化，重启进度不丢）
cd F:\Robot_Project\LogisticsData_Sim
npm install && npm start      # 控制台 http://127.0.0.1:5288/（时钟/倍速/启停/事件流/排产参数）

# 2) 再启动本系统，沙盘加 ?feed=all 打开 —— 开任意多个窗口/实例，消费同一条事件流，同样进度
cd F:\Robot_Project\Robot_Sim
npm run sim                   # http://localhost:5199/?feed=all
```

沙盘侧 URL 参数：`?feed=all` 接入数据源并**全量回放**（从流头消费整条流，期初按数据库种子分布重建；
同一标签页刷新自动断点续接，不重复入库）；`?feed=live` 只跟最新事件（跳过历史）；
`?view=1` 只读观景窗口（不写回库存数据库/不落台账/不归档场次，多开对照安全）；
不加 `?feed` 为本地排产模式；`?logi=<url>` 覆盖数据源地址。
数据源控制台重置事件流后，运行中的沙盘与「进厂确认」页都会自动检测并把游标重新对齐到流头
（数据库侧登记按 车牌+运单 去重，重放同一段流不产生重复台账）。
**同步口径**：物流源模式下「进厂确认」（pending/confirmed）、「车辆记录」台账与沙盘 `?feed` 消费的进厂车事件 1:1 对应，
按 车牌+运单 匹配确认单执行落位；沙盘 KPI「今日进厂车辆」额外包含**出厂空车**且按仿真日切片，数值与台账自有出入（口径见沙盘 KPI 注释）。

## 技术栈

- **页面**: 原生 HTML/JS/CSS 页面（无构建步骤），Three.js 由 `npm run vendor:three` 内联生成；工作台类页面的公共样式/导航/工具函数抽至 `simulation/shared/`（经典脚本 + 全局 `SIM` 命名空间，零构建，详见 `simulation/shared/README.md`）
- **后端**: Node 内置 http + better-sqlite3（零框架依赖）
- **垛位推荐算法**: 独立项目 [`F:\Robot_Project\StackAlloc`](../StackAlloc)（垛位推荐算法包，零依赖纯函数）——
  入库归堆评分 / 出库选捆 / 倒垛落点 / 垛容几何 / 监测范围的**唯一实现**。服务端经 `server/stack-alloc.js` 引入（Node ESM 相对路径，无需安装）；
  浏览器端由 serve.mjs 把包源码现算成经典脚本、在页面 `/*@@stack-alloc@@*/` 占位处内联注入（与 core-seg 注入同一机制，无头自测同口径）。
  算法包需与本仓库同级放置（`F:\Robot_Project\StackAlloc`），否则启动即报模块缺失；改动算法后跑 `npm test`（在 StackAlloc 目录，包自测）+ `npm run db:test` 验证

## 进厂确认 → 算法优化闭环

1. 「模拟车辆进厂」取物流数据源的下一辆进厂车（车牌/运单/配载与沙盘同一条事件流，本页独立游标；数据源离线回退本地随机，真实识别系统接入后替换）；
2. 服务端按归堆评分（同规格归堆/空垛兜底/库位同族/邻位聚簇/扫码干扰）生成垛位分配推荐，同规格集中码放、垛满拆垛；评分口径与沙盘同源（`stackCap` 物理垛容 + 监测范围约束）；
3. 管理工逐组确认或改垛，确认后下发；
4. 沙盘消费同一条物流事件流建入库任务时，按「车牌 + 运单」匹配已确认分配单（`/api/inbound/match`）：命中即按确认落位执行（**确认下发 = 现场执行**），车辆身份（车牌）随事件流贯穿到货车与场次留档；
5. 该车卸货完毕离场时回传 `/api/inbound/:id/unload`，台账置 completed 并记离场时间——确认、执行、台账三点闭环；
6. 被改动的组在推荐落点与实际落点上逐维度复算评分，人工选择更优的维度权重 +2、更劣 -2（按 schema 夹取），
   写回 `sim_params` —— 沙盘与推荐算法下次即按新权重执行。

## 本地数据库（库存/库位）

基于 Node + SQLite（better-sqlite3），存储「库位 → 10 垛 → 每垛 ≤400 捆（实际按限高收窄）」的库存数据。
数据库文件为 `server/warehouse.db`（不提交 git，可用命令随时重建）；主应用种子数据在 `server/data/*.json`。

### 表结构
- `specs` — 棒材规格（名称/单捆吨重/渲染色）；捆制口径：一捆合起来的直径默认 15~50cm（可在「库房参数设计」页调整），每捆支数 = `spec_rules` 覆盖 > `server/database.js` 的 `SPEC_DIMS` 预置 > `deriveRods()` 按捆径口径自动推导（`bundleDiaCm()` 核算捆径），细棒材增多支数成大捆（如螺纹钢 Φ20 = 21 支/捆），Φ200 起大口径管单支吊运不打带
- `spec_rules` — 捆制规则覆盖（每规格每捆支数；0 = 引擎自动推导，无行 = 预置值，「库房参数设计」页编辑）
- `storage_slots` — 库位（编码/分区/号区/跨/是否整跨合并/状态）
- `stacks` — 垛（库位+垛号，同垛单一规格，count ≤ 垛容（通用上限 400、按规格限高收窄），pending 待扫码，in_time 最早入库时间）
- `sim_params` — 调度规划参数（key 形如 `placement.sameSpecBase`）
- `inbound_vehicles` / `inbound_loads` — 进厂车辆与其垛位分配（推荐值 + 最终值）
- `placement_feedback` — 确认/调整留痕（推荐落点、最终落点、触发的权重变化）
- `app_warehouse` / `app_spans` / `app_locations` / `app_coils` / `app_tasks` — 主应用（三维库区）数据

### 与操作端（kg-dispatch-frontend）联调

# 3) 操作端（另开终端，F:\Robot_Project\kg-dispatch-frontend）

## 项目结构

```
simulation/            # 5199 静态站点（无构建）
├── serve.mjs          # 静态服务器（含沙盘公共片段占位注入）+ 一站式拉起数据库 API
├── feed-stub.mjs      # 物流数据源桩（复用 LogisticsData_Sim 真实生成器，无头自检共用）
├── sandbox-page-loader.mjs  # 自测注入：沙盘公共片段占位替换（与 serve.mjs 同口径）
├── tool-split-sandbox.mjs   # 一次性工具：生成 2D/3D 沙盘公共片段库 shared/sandbox-core.mjs（自带稳定预检+还原校验）
├── shared/            # 全站公共层（tokens.css / base.css / nav.js / sim-common.js，详见 shared/README.md）
│   ├── tokens.css     # 设计令牌 + embed 模式规则
│   ├── base.css       # 工作台页公共布局样式
│   ├── nav.js         # 顶部导航注入（统一链接表 + 当前页高亮）
│   ├── sim-common.js  # SIM 工具（DB_API/api()/esc/SPEC_COLORS/fmt*/msg…）
│   ├── README.md      # 公共层与沙盘合并机制说明
│   └── DRIFT-DECISIONS.md  # 去重改造漂移裁决清单
├── 调度仿真沙盘.html   # / 仿真沙盘（车辆事件从物流数据源 5288 增量拉取）
├── 调度仿真沙盘3D.html # /3d 三维仿真沙盘
├── 进厂确认.html       # /inbound 管理工垛位确认/调整 + 学习面板
├── 车辆记录.html       # /vehicles 车辆进出场记录（API 驱动）
├── 扫描时效记录.html   # /scans 扫描任务历史完成情况与延时统计（读沙盘任务台账 localStorage）
├── 仿真场次记录.html   # /runs 仿真场次留档
├── 调度参数.html       # /params 调度规划参数
├── 库房参数设计.html   # /whcfg 捆制规则/库房尺寸/垛容/充电位置
└── *.mjs              # 自检/探针脚本（node simulation/self-test.mjs 等）
server/                # 数据库与 HTTP API（127.0.0.1:3001）
├── index.js           # 路由
├── database.js        # 建库/迁移/库存读写
├── inbound.js         # 进厂确认：物流源车辆识别（含后台自动进厂轮询）/归堆推荐/确认调整/权重学习
├── params.js          # 调度参数 schema（与沙盘共用）
├── layout.js          # 库区布局生成（91 库位）
├── data/*.json        # 主应用种子数据
└── warehouse.db       # SQLite 库文件（自动创建）
../LogisticsData_Sim/  # 车辆进出库物流数据仿真（独立程序，唯一车辆数据源）
```
